# 技术细节

命令行解析、退出码和日志格式的参考。第一次使用请看 [README](../README.md) 里的用法；在 Linux 上用 Steam + Proton 运行请看[在 Steam + Proton 上运行](running-on-proton.md)。

## 命令行选项

```
EndfieldNoLauncher.exe --game "<完整路径>\Endfield.exe" [选项] [-- <游戏参数>]
```

| 选项 | 含义 |
| --- | --- |
| `--game <路径>` | 必填。游戏 `Endfield.exe` 的完整路径，文件名必须正好是 `Endfield.exe` |
| `--parent <路径>` | 可选。官方 `Games.exe`，省略时自动查找 |
| `--hide-console` | 分离控制台，失败时改用对话框报告。供快捷方式或其他启动器调用 |
| `--` | 其后的每个参数都原样转发给游戏 |
| `--help`、`-h`、`/?` | 打印用法后退出 |

取值选项只接受出现一次：重复的 `--game` 或 `--parent`，以及末尾缺少取值的 `--game`，都被当作无效参数并以退出码 2 结束。`--game` 的路径会先转成绝对路径，再检查文件是否存在。

## 退出码

| 码 | 含义 |
| --- | --- |
| 0 | 游戏以 0 退出，或请求了 `--help` |
| 2 | 命令行无效 |
| 4 | 启动器父进程或游戏进程创建失败，或发生未预期的异常 |
| 7 | 未找到签名有效的官方启动器 |
| 8 | 等待游戏退出或读取其退出码失败 |
| 其他 | 游戏自身的退出码，原样转发 |

由于游戏退出码被原样转发，自身以 2、4、7、8 退出的游戏与这些 helper 失败仅凭退出码无法区分。退出前打印的诊断文本可以区分它们。

## 日志

每次运行都会在**可执行文件旁边**追加写入 `EndfieldNoLauncher.log`，逐行带时间戳，UTF-8 编码。由 Steam、快捷方式或其他启动器发起的运行没有可见控制台，因此这个文件是唯一的记录。

日志在解析命令行之前就已打开，所以被拒绝的命令行也会出现在其中。首行是完整命令行，末行是退出码。如果启动后该文件不存在，说明可执行文件从未运行。

日志能记录整个启动过程，是因为内核写入 `std::wcerr`，而该流被镜像进文件。写日志是尽力而为：当可执行文件所在目录不可写时，运行继续，仅保留控制台与对话框报告。

## Steam 的启动选项

把可执行文件添加为「非 Steam 游戏」时，参数放「启动选项」字段，不要放「目标」字段——后者只接受可执行文件路径：

| 字段 | 值 |
| --- | --- |
| 目标 | `<安装目录>\EndfieldNoLauncher.exe` |
| 起始位置 | 任意可读目录；游戏与启动器路径都是绝对路径 |
| 启动选项 | `--game "C:\...\Endfield.exe" --parent "C:\...\Games.exe"` |

`C:\...` 由 Steam 运行该可执行文件时所用的 prefix 解析，因此这些路径必须指向该 prefix 内的文件。在 Linux 上这意味着为此快捷方式强制指定 Proton 兼容性工具，具体步骤见[在 Steam + Proton 上运行](running-on-proton.md)。

不含 `%command%` 的启动选项字符串会被 Steam 追加到目标命令之后，因此本可执行文件能完整收到自己的参数：

```
--game "C:\...\Endfield.exe" --parent "C:\...\Games.exe"
```

要用另一个程序包装启动过程（gamescope、mangohud），字符串必须包含 `%command%`，Steam 会把它替换为目标命令，本工具自己的参数跟在占位符之后：

```
gamescope -w 2560 -h 1440 -fb -- %command% --game "C:\...\Endfield.exe" --parent "C:\...\Games.exe"
```

没有占位符时，包装程序会被追加，本工具的第一个参数就变成包装程序的名字，并以退出码 2 结束。参数被拆成多个词送达时同样解析失败，因此两条路径都需要各自的引号。
