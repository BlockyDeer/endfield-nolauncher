# EndfieldNoLauncher

[简体中文](README.md) | [English](README.en.md)

Starts 《明日方舟：终末地》 / Arknights: Endfield on Windows x64 without
opening the official Hypergryph launcher window.

This project is a feature extraction from
[Better-Endfield](https://github.com/Dr-hydra/Better-Endfield), for people who
do not want the pile of extra features that comes with it.

> [!WARNING]
> The vast majority of this repository is generated by an LLM, and no warranty
> of any kind, express or implied, is made about code quality, documentation
> quality, or anything else.

The client validates its **direct parent process**: the parent file must be
named `Games.exe`, carry a trusted Authenticode signature, and be signed by the
official Hypergryph organization. Launching `Endfield.exe` directly fails with
`errorCode 10100` and a "start the game from the official launcher" prompt.

This tool satisfies that check without running the launcher UI. It creates the
official `Games.exe` **suspended**, never resumes it, and assigns it as the
parent of the game process. Nothing is injected, no launcher code executes, and
no game file is modified.

## Scope

In scope: starting the game so it passes the parent-process check.

Out of scope, by design: model replacement, camera, MMD, voice routing, UI
changes, combat statistics, Steam integration, module loading — every other
feature of the project this core was derived from. There is no injection path
and no module loader in this program.

## Requirements

- Windows 10/11 x64
- The official CN Hypergryph launcher installed and validly signed. Without it
  the tool exits with code 7 and starts nothing.
- The game executable must be named `Endfield.exe`
- Elevation: the game itself requires administrator rights, so a normal UAC
  prompt is expected. Allowing it is part of the normal flow.

## Usage

The steps below are for Windows. To run on Linux with Steam + Proton, see
[running-on-proton.md](docs/running-on-proton.md) (Chinese only); most of the
usage is the same.

### Put the program somewhere

`EndfieldNoLauncher.exe` needs no installation; any folder works. A dedicated
one such as `D:\NoLauncher\` is a good idea.

### Find the game path

The program needs the full path of the game's `Endfield.exe`. The most reliable
way to find it is to start the game normally first: press `Ctrl + Shift + Esc`
for Task Manager, find `Endfield.exe` under Details, right-click it and pick
Open file location. Click the address bar of the window that opens to read the
full path.

Write it down, for example:

```
D:\Hypergryph\Games\Endfield\Endfield.exe
```

> The file name must be exactly `Endfield.exe`. If you found `Games.exe`, that
> is the launcher, not the game.

### First run: an elevated command prompt

Run it from the command line the first time, because that is the only way to see
the error text; a double-click closes the window before you can read anything.

The game itself requires administrator rights, so this program must run elevated
as well, or it fails with `创建游戏进程 / Create game process (Win32 740)`.

Press `Win`, type `cmd`, right-click Command Prompt, pick Run as administrator,
and accept the UAC prompt. Then run (with your own paths):

```cmd
cd /d D:\NoLauncher
EndfieldNoLauncher.exe --game "D:\Hypergryph\Games\Endfield\Endfield.exe"
```

Keep the double quotes: the path may contain spaces.

When everything works the game starts directly and the launcher window never
appears. The console window stays open until the game exits — that is expected;
it waits for the game and forwards the game's exit code.

`--parent` is normally left out: without it the program finds the installed
official launcher itself, verifies candidates from the highest version down, and
uses the first that passes; when none passes it prints a message and exits with
code 7.

Check the exit code afterwards; it is useful when reporting a problem:

```cmd
echo %ERRORLEVEL%
```

### Everyday use: a shortcut

Once the test run works, make a shortcut and use that from then on.

Right-click in `D:\NoLauncher\`, pick New → Shortcut, and enter (with your own
paths):

```
"D:\NoLauncher\EndfieldNoLauncher.exe" --hide-console --game "D:\Hypergryph\Games\Endfield\Endfield.exe"
```

Name it, for example "Endfield (no launcher)", and finish.

Then right-click the shortcut → Properties → Shortcut → Advanced → tick Run as
administrator. This step is required; without it the game process cannot be
created.

`--hide-console` removes the console window. With it, a failure is reported in a
dialog instead.

### Passing game arguments

Arguments for the game itself go after `--` and are forwarded unchanged:

```
"...\EndfieldNoLauncher.exe" --hide-console --game "...\Endfield.exe" -- -logFile "D:\log.txt"
```

### Launching from Steam or another launcher

Put the arguments in the launch options field, not in the target field, which
takes the executable path alone; the game path and the launcher path each need
their own double quotes. How Steam concatenates that string, and why a wrapper
(gamescope, mangohud) must include `%command%`, is in the
[technical details](docs/technical-details.md) (Chinese only).

### When something goes wrong

A run started by a shortcut or another launcher produces no visible output, so
look at `EndfieldNoLauncher.log` **beside the executable**. Exit-code meanings
and how to read each log line are in the
[technical details](docs/technical-details.md) (Chinese only).

### Game updates

A major update still goes through the official Hypergryph launcher. This program
does not update the game and modifies no game file.

### Enjoy the game

That is the whole setup; start the game.

## How it works

1. **Discover** the launcher installation from the `hypergryphlauncher*`
   registry protocol, the uninstall entries named 鹰角启动器 / Hypergryph
   Launcher, and `%ProgramFiles%`, `%ProgramFiles(x86)%`, `%LOCALAPPDATA%`.
2. **Verify** a candidate: the file must be named `Games.exe`, `WinVerifyTrust`
   must accept its signature, and the signer certificate's organization must be
   the official publisher. The open file handle is held from verification
   through process creation so the executable cannot be swapped in that window.
3. **Create it suspended** with `CREATE_SUSPENDED | CREATE_NO_WINDOW`. The
   primary thread is never resumed, so the launcher never runs and never shows
   a window; only its image and signature exist, which is all the check reads.
4. **Create the game** with `EXTENDED_STARTUPINFO_PRESENT` and
   `PROC_THREAD_ATTRIBUTE_PARENT_PROCESS` pointing at the suspended launcher,
   which makes the launcher the game's direct parent.
5. **Wait** for the game to exit and return its exit code. Teardown terminates
   the suspended launcher only if this process created it and it is still
   running, then waits for it to actually stop.

## Build

MSVC:

```powershell
cmake -B build -G Ninja
cmake --build build
```

Cross-compile from Linux with mingw-w64:

```bash
cmake -B build -G Ninja -DCMAKE_TOOLCHAIN_FILE=cmake/mingw-w64-x86_64.cmake -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

Both toolchains link the C runtime into the image by default, so the produced
`EndfieldNoLauncher.exe` runs beside the game with no redistributable and no
extra DLL. The switch changes only the deployment shape:

| `NOL_STATIC_RUNTIME` | Release size (mingw) | Runtime DLLs needed on the target |
| --- | --- | --- |
| `ON` (default) | ~1.2 MB | none |
| `OFF` | ~122 KB | `libstdc++-6.dll`, `libgcc_s_seh-1.dll`, or the MSVC redistributable |

Pass `-DNOL_STATIC_RUNTIME=OFF` for the smaller executable and ship the listed
DLLs next to it.

## Tests

```bash
cmake --build build --target EndfieldNoLauncherTests
build/EndfieldNoLauncherTests.exe
```

`tests/options_tests.cpp` covers command-line parsing and `CreateProcessW`
argument quoting, including the trailing-backslash and embedded-quote cases
that silently corrupt a command line when unhandled.

**The launch path itself is not covered by an automated test.** It requires a
signed official launcher, the installed game, and elevation, so it must be
verified on a real Windows installation. Compiling successfully says nothing
about whether the game accepts the parent process.
